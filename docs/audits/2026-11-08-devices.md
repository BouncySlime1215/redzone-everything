## S2 findings

### DEV-01 CONFLICT S2: Peacock can be picked and tuned
- Files: redzone/discovery/providers.py:60,77,81,97 (provider, TUNER_APPS, LINK_APPS, LAST_RESORT), :493-540
  (`_link_source`), :1023 (`best_source`); redzone/tuners/providers.py:233-246 (`PeacockTuner`), :396 and :408
  (registered), redzone/discovery/runtime.py:37 (`register(TUNERS)`); redzone/control.py:1672 (`can_tune`) has no app ban;
  redzone/default_config.yaml:858-859 (`priority.enabled: false`, `banned_apps: [peacock]`).
- Evidence: `LAST_RESORT = frozenset({"peacock"})` ("the last resort"), `tunable = bool(ref) and app in TUNER_APPS`
  with "peacock" in `TUNER_APPS`. `best_source` ranks it last but still returns it when it is the only candidate, and a
  phone "you set it" pick wins untouched. The ban `rank(): if g.app and g.app.lower() in rules.banned_apps: continue`
  (redzone/noggin/priority.py:196) runs only when `noggin.priority.enabled` is true, which defaults to false.
  redzone/channels.py:52 (`APP_FOR["peacock"] = None`) treats Peacock as unwatchable, so ChannelMap and discovery disagree.
- Why it matters: CLAUDE.md says "Never use Peacock". Today the only thing stopping a `peacock:<pvid>` tune is that no
  event link was found or the app is not installed/signed in on the stick (plan.py:44 says it is signed in on one stick).
- Fix: remove "peacock" from `TUNER_APPS`, `LINK_APPS` and `EXTRA_TUNERS`, or filter `banned_apps` inside
  `best_source`, `gather_sources` and `Controller._tune` (refuse any `peacock:` target) independent of the Noggin flag.
  Keep `peacock_on_yttv` (it offers NBC/NBCSN on YouTube TV, which is fine).
- Test: feed `gather_sources` a link record `{"peacock": [{"ref": "x"}]}` and assert no pick or tuner for it; assert
  `Controller._tune(stick, "peacock:x")` returns "no tuner" with the flag off.

### DEV-02 ERROR S2: only the first TV path is ever tried
- File: redzone/tv.py:742-783 (`set_input`); caller redzone/control.py:3038-3066.
- Evidence: the loop `for m in order:` ends every branch with `return ok` (line 765, local) or `return False` (line 780,
  smartthings). `paths()` (tv.py:438) returns up to two methods, but only the first runs. The comment justifies this for an
  *ambiguous* delivery. It also fires for a *definite* non-delivery: SmartThings 401/403/429/5xx gives `accepted=None`,
  and a local `key()` that fails with a refused connection also gives `accepted=None`.
- Why: with `input_method == "smartthings"` and a dead cloud, every flip fails on SmartThings, then `_flip_to` falls to
  HOME (kills the player; Prime comes back after 57-73 s per docs/instant-switching.md). The working local key is
  skipped until `_note` backs SmartThings off (two failures, 300 s, tv.py:462), and then it repeats after 300 s.
- Fix: continue to the next method when the failure is definite (HTTP status error before send, `_never_sent`,
  connection refused, breaker open, token missing). Return only on an ambiguous timeout.
- Test: fake SmartThings that returns 401; fake local that works; assert `set_input("HDMI2", methods=["smartthings","local"])`
  returns True via local and `last_input.source == "local"`.

### DEV-03 ERROR S2: verify loop can hold a flip for a minute or more
- File: redzone/tv.py:691-724 (`_verify_input`), :575 (8 s timeout), :217 (10 s token timeout).
- Evidence: `n = ... VERIFY_READS if self.has_readback`, each read is `input_status()` -> `_st` -> up to 8 s (plus
  `st_discover` and a token refresh of up to 10 s). The only early exit is `if self.cloud_blocked(): break`, and
  `cloud_blocked()` returns "" unless `hardening.smartthings` is on (tv.py:385). `has_readback` is true whenever a
  device id and a token file exist, even if the cloud is dead.
- Why: after the local key was already sent, the flip waits `8 x (timeout + 0.3 s)`. Cloud unreachable: up to ~64 s. After
  Dec 15 (fast 401/403): at least 8 x 0.3 s + 8 round trips (~3-6 s) of dead air per flip, before the key is even
  trusted. `TV_FLIP_MAX_S = 6.0` only logs it. `tv_flip_prior_s` (1.89 s) plans for none of this.
- Fix: stop reading after the first fast failure of a call (non-200 status, auth error); bound the whole verify by a
  deadline (~2.5 s); always use the breaker for the verify path, not just under `hardening`.
- Test: transport that raises ConnectTimeout; assert `set_input` with a trusted local key returns in under 3 s.

### DEV-04 GAP S2: nothing covers the end of free SmartThings access (Dec 15 2026)
Every code path that needs SmartThings, and what covers it:

| path | needs ST | local / CEC fallback |
|---|---|---|
| `SamsungTV.st_input` / `set_input("smartthings")` (tv.py:652, 766) | yes | local key works only if `local_input_verified` (tvsetup) |
| `input_status` readback (tv.py:663), used by `_verify_input`, `Controller._sync_from_tv` (control.py:612), onetouchplay verify (control.py:3086-3093) | yes | none. CEC corroboration returns None when CEC is off (control.py:595-600), which is the shipped setup (`keep_cec_off`) |
| `Controller.sync_active_from_cec` drift detection every 30 s | uses ST first, then CEC | CEC flags with CEC off report nothing, so someone using the remote goes unseen |
| tvsetup `--smartthings` (tvsetup.py:388-410, `create_oauth_app`) and the whole OAuth file | yes | cannot create or edit apps after Nov 4; keys deactivated Dec 15 |
| planner `flip_path()` (control.py:1711) and `ready()` (tv.py:434) | `cloud_ready` counts a configured token as ready | none; planner keeps costing a ~2 s TV flip while HOME flips happen |
| Health `tv_auth` / `tv_cloud_down` (platform/health.py:124-135) | only when hardening on | silent when hardening off (default) |
| default_config.yaml:594 `tv_flip_prior_s` | measured on SmartThings, not on the local key | none |

- Why: on Dec 15 the only remaining proof that a flip landed is "key delivered + setup proved the key" (`evidence.trusted`).
  Local keys are not read back, so a TV that ignores a key (the research notes this for `KEY_HDMIx`) or sits on another
  input is accepted. There is also no phone alert (health needs hardening).
- Fix (ordered): (a) make `cloud_ready`/`has_readback` require a recent successful ST call; (b) turn Health tv_auth and
  the breaker on regardless of `hardening.smartthings`, with a "ends 2026-12-15" banner; (c) add a stick-side proof that
  needs no cloud: with CEC on at the moment of the flip, `_cec_corroborate`; or a screencap/OCR sanity check on the stick
  that should be on screen (`stick.screen` is the stick's own output, so use it only as a "this stick is awake" check);
  (d) re-time the local flip and replace `tv_flip_prior_s`; (e) write the runbook step to run `scripts/tv_setup.py` with
  CEC left on for proof; (f) ask Nick before any paid plan ($0 rule).
- Test: run the control tests with the fake SmartThings returning 403 and assert flip time, planner path and the health
  alert.

### DEV-05 ERROR S2: sticky `input_method`
- File: redzone/tvsetup.py:559 `tv["input_method"] = tv.get("input_method") or "local"`; redzone/tv.py:440
  (`if self.method == "smartthings" and self.cloud_ready: out.append("smartthings")` comes first).
- Evidence: a re-run of tv_setup that proves the local key keeps an old "smartthings" value, so SmartThings stays the
  first path. Combined with DEV-02 this makes the dead cloud the primary path.
- Fix: when local is proven, prefer "local" (write it) and keep SmartThings only for verify; in `paths()` order local first
  when `local_ready`.
- Test: devices.json with `input_method=smartthings` and a proven local key; `paths()[0] == "local"`.

### DEV-06 ERROR S2: wrong deep link on relaunch for search-tuned YouTube TV channels
- File: redzone/control.py:3153-3178 (`_relaunch`, url at 3169); redzone/tuners/tuners.py:375 (`YouTubeTVTuner.url`);
  redzone/control.py:1967-1974 (`_ref`).
- Evidence: `_ref("youtubetv:nbcsn")` returns `"search:nbcsn"` (or `search:local:...`) when no watch code exists, and
  `_relaunch` does `url = tuner.url(ref)` which gives `https://tv.youtube.com/watch/search:nbcsn`. `YouTubeTVTuner.tune`
  special-cases the `search:` prefix; `url()` does not.
- Why: after a HOME flip (the fallback, and the default after Dec 15 if DEV-02 stays) a stick that was playing NBCSN or a
  local station relaunches into an error page or home, not the game. A fault in `_reassert` does the same.
- Fix: in `_relaunch` skip the link when `ref.startswith("search:")` and use the package resolve-activity branch (the app
  comes forward on its player), or raise in `url()` for search refs.
- Test: HOME flip with `on_target == "youtubetv:nbcsn"`; assert no `watch/search:` URL is sent.

### DEV-07 ERROR S2: local path blackout for 300 s
- File: redzone/tv.py:455-465 (`_note`), :349 (`local_ready`), :523 (`warm`).
- Evidence: two failed local keys in a row (TV briefly unreachable, Wi-Fi blip, TV in standby) set
  `_skip_until["local"] = now + 300`. `local_ready` is then False, `warm()` returns False immediately, and no probe ever
  clears it. `Controller.keepalive` keeps skipping it. Every flip in that window is HOME.
- Fix: probe in `maintain()` while backed off (open the socket; clear the backoff on success), shorten the backoff to
  ~30-60 s, and `wake.recover` should clear `_skip_until`.
- Test: two failed keys, then a good `warm()`; assert `local_ready` is True.

### DEV-08 GAP S2: search tune presses keys with no cut-window check
- File: redzone/tuners/tuners.py:383-430 (`_tune_by_search`), redzone/tuners/yttv_search.py:718-760 (`hunt_channel`).
- Evidence: `require_cut(may_cut, steps, mutating=True)` is called once (tuners.py:401); `hunt_channel(...)` takes no
  `may_cut` (signature at yttv_search.py:718) and presses DPAD/CENTER for up to `HUNT_BUDGET_S = 120.0`.
  Every other tuner calls `require_cut` before each visible key.
- Why: on the visible stick (single-stick mode, or a re-tune of the screen stick) the window can close mid-hunt and the keys
  still go out. On the hidden stick it is harmless to the picture but holds the stick for up to two minutes.
- Fix: pass `before_key=lambda: require_cut(may_cut, steps, mutating=True)` into `hunt_channel` and call it in `press()`.
- Test: `may_cut` that goes False after the first key; assert the hunt stops with CutWindowClosed and sends no more keys.

### DEV-09 GAP S2: stick/HDMI map is trusted blindly
- Files: redzone/control.py:459-473 (`load_devices`, `self.hdmi` from devices.json), redzone/autonomy.py:805
  (`if not e.get("hdmi")`), redzone/tuners/adb.py:415 (`hdmi_port`).
- Evidence: `hdmi_port()` is read only when the stored value is empty. A stick moved to the other HDMI port, or a DHCP
  change that puts the other stick on a known IP, keeps the old mapping. `_verify_input` checks that the TV is on the
  requested input, never that the stick behind it is the intended one. With the cloud readback gone (DEV-04) nothing can
  notice.
- Why: "flip to the hidden stick" would show the wrong game; Rule #1 depends on the hidden stick being the one we tuned.
- Fix: at start and on reconnect compare `hdmi_port()` (works when CEC is on; when off, compare the serial/MAC from
  `stick_identity` to devices.json) and mark two-stick mode "degraded" with a phone alert on mismatch.
- Test: devices.json says .181 = HDMI1; fake `hdmi_port` returns HDMI2; assert `two_stick_why() != ""`.

## S3 findings

### DEV-10 ERROR S3: keepalive blocks on TV maintenance
redzone/control.py:797-799 awaits `self.tv.maintain()` inline. tv.py:673-689: `auth.maintain()` (10 s timeout) +
(hardened) probe + `warm()` (up to 12 s). The TV in standby or off makes this slow once per `TV_MAINTAIN_S = 60`, and the
reconnect, CEC sync, watchdog and visible-stick checks that follow wait. Fix: run it as a background task with a
timeout. Test: a `maintain` that sleeps 20 s; assert keepalive returns in under 2 s.

### DEV-11 ERROR S3: `-W` with a 15 s timeout
redzone/tuners/providers.py:152 and :133 (`command` always contains `am start -W`); `Stick.view` uses 30 s for `-W`
(adb.py:439, "a cold start on the 2018 stick can top 15 s"). A slow Fubo/Max/Paramount cold start hits the 15 s timeout,
which calls `breaker.hang()`; two in a row open the stick breaker and block everything on that stick for 10 s+. The AdbShell
is also killed (adb.py:652). Fix: timeout 30 for `-W`, or drop `-W` and watch playback. Test: fake shell that replies
after 20 s.

### DEV-12 ERROR S3: dead `press_after`
redzone/tuners/providers.py:182-226: `_watch` passes `scheduled=due` to `_read_screen`, which passes it to
`_keys_for(text, scheduled)`; that method (226-229) never reads `scheduled`. The `press_after` values on the Peacock, NFL,
NBA, Apple TV and DAZN tuners ("press OK if a play button shows") do nothing beyond an early screen read. The docstring
promises more. Fix: implement it or delete it. Test: a play-button screen at t=8 s expects a CENTER only when scheduled.

### DEV-13 ERROR S3: stick sleep settings applied once
redzone/control.py:984-989: `_watchdog_applied` is one flag for both sticks; only sticks in `usable` at the first tick get
`settings put ... sleep_timeout`. A stick that was offline then, rebooted later, or took a Fire OS update (the research
notes updates may reset them) is never re-applied, and is never read back. Fix: per-stick flag, cleared in `_forget`, plus a
`settings get` read-back. Test: connect stick B after the first tick; assert B gets the settings.

### DEV-14 ERROR S3: identify
redzone/tuners/adb.py:270-293. (a) `lines = r.out.splitlines()` is not guarded by `r.ok`, so a breaker message or
"timeout/error..." becomes `self.model`. (b) `controllable` rejects only model codes listed in `MODELS` as Vega, so an
unlisted Vega model (new 2026 sticks) is treated as Fire OS. The research (finding 1) wanted a software-line check.
(c) `_reconnect` (control.py:1011) calls `identify()` only when `packages` is empty, and devices.json pre-fills it, so model
and packages are never refreshed after a stick swap. Fix: check `r.ok`, read `ro.build.version.release` and Vega markers,
re-identify on each reconnect after a drop, and verify the model codes (AFTCA002, AFTCL001, AFTCR001, AFTMA08C15 are
unverified from Amazon's table).

### DEV-15 CONFLICT S3: unauthorized
adb.py:6 says "unauthorized -> stop and tell you to approve the prompt". `connect` (adb.py:238-268) only sets
`state = "unauthorized"` and `_reconnect` calls it again at every tick (~9 s), re-sending `adb connect` forever. On Fire OS
that can re-raise the on-TV prompt over the game. Fix: stop retrying while `state == "unauthorized"` (retry after 5 min).

### DEV-16 ERROR S3: shared websocket, no lock
redzone/tv.py:482-534. `key()` and `warm()` each run `to_thread` on the same `self._tv`; `wait_for` cannot cancel the thread,
and `_drop_local()` closes the socket another thread may be sending on. A flip racing the minute-by-minute `warm()` can lose
its key. Fix: one `asyncio.Lock` around local operations (take it with a short timeout in `key`).

### DEV-17 ERROR S3: diagnosis adds latency to failures
redzone/tuners/providers.py:377-394 (`DiagnosingTuner.tune`): after any failed YouTube TV/Prime/ESPN tune it awaits
`stick.screen_text()` (uiautomator 12 s + screencap 8 s + OCR 8 s). Failed tunes return up to ~28 s late and the stick is
busy meanwhile. Fix: bound with `asyncio.wait_for(..., 4)` and skip when the cut window has closed.

### DEV-18 GAP S3: onetouchplay verify uses ST only
redzone/control.py:3084-3093: `observed = await self.tv.input_status(); ok = observed == requested`. With the cloud gone
this is always None, so the branch reports "could not be verified" even when `onetouchplay` worked, and never uses
`tv.corroborate`. Fix: call `self.tv._verify_input` equivalent (readback then CEC).

## Checked against the two research notes
- Research finding: YTTV package-only intent. `YouTubeTVTuner` sends a VIEW with the package, no activity (tuners.py:375,
  adb.py:438): correct.
- Research: ESPN native `sportscenter://` link. Not used; `EspnTuner.url` uses the web link. Not a bug; no A/B exists.
- Research: Vega guard, sleep read-back, cold-start flag: not implemented (DEV-13, DEV-14).
- Research: one adb client at a time. `Stick.connect` offers no hint ("another adb client may hold the stick").
- Research: Samsung numbered keys are model-dependent. The `local_trusted` gate (tvsetup `test_local_inputs` +
  `local_proven`, run twice per input, eyes or CEC) is correct. Its one weakness is that the proof is CEC-based and the
  shipped setup then turns CEC off (DEV-04).
- Research: SmartThings deadline Dec 15 2026. See DEV-04.

## What is solid
- adb.py persistent shell: random per-command marker, subshell, `</dev/null`, never resends a key or `am start`
  (`_repeatable`, LOST/TIMED_OUT handling), 3 s handshake check, killed on timeout, breaker around hangs.
- Reconnect is a fixed ~9 s retry forever, `adb connect` capped at 6 s, `probe_now()` after wake and reconnect.
- Wake recovery (platform/wake.py) drops the TV socket, probes breakers, and presses no key.
- tv.py: a key is not confirmation; `trusted` needs a setup-proven key AND no contrary readback; HOME on the same
  destination is the only fallback after an ambiguous send; tokens are written 0600 with atomic replace; the OAuth file is
  re-read when another process rotates the refresh token; 401 renew-once, 429 Retry-After, POSTs never retried.
- Deep links: package-only YTTV intent survives activity renames; Prime keeps `-W`; the `fresh` relaunch handles "brought to
  the front"; refs are checked by `_SAFE_REF` and an origin allow-list for provider tuners.
- Purchase and account walls: `is_purchase_screen` stops every OK press; profile selection needs exact label plus visible
  focus; "Watch live" is pressed once per link.
- `ChannelMap.APP_FOR["peacock"] = None` and `PEACOCK_ON_YTTV` correctly send Peacock games to NBC/NBCSN on YouTube TV
  (the gap is only that discovery lets Peacock through separately, DEV-01).
- Tuners check `require_cut` before every visible mutation (except DEV-08), and `ensure_awake` refuses to wake a stick when
  the cut window is closed.
