## What's solid
- Single-writer, atomic state files: `userstate.save`, `deploy._atomic_json`, `Config._save` (tmp then replace), `Snapshots` content
  addressing with a check that every blob exists before restoring anything.
- `userstate` round-trips pause, hold, lock, focus, skips and their expiries; stale game choices drop after 6 h.
- `Store`: a corrupt database is set aside (never deleted) and a fresh one started; WAL checkpoint and size cap in `rule_logs`; `prune()` is called.
- Supervisor: every fix goes through one rate limiter with a minimum gap and an hourly cap, each logged; a failing rule never stops the loop
  (`step` catches per rule); `rule_screen` re-checks that nothing started after its awaits before pressing a key; mutes reset on a restart by design.
- Watchdog design: verify-after-fix (`settle`), failed-fix memory so the ladder moves up, `deploy_in_progress` stand-down, launchd EX_CONFIG
  detection instead of a restart loop, notify throttling, no model in eco/critical.
- Web guardrails: private-address allow list, DNS-rebinding Host check, Origin/Sec-Fetch-Site check, `application/json` required for bodies,
  `/api/agent/fix` local only, image proxy restricted to ESPN image paths with no traversal, `Cache-Control: no-store` on the API.
- Deploy: tests on a detached worktree (never the live checkout), a lock, `confirm`/`rollback` commands, rollback verifies the app came up,
  `rollback_failed` blocks further deploys until a person looks.
- Logging: the service log is a RotatingFileHandler (5 MB x 3), stdout/stderr redirected into it, `httpx` logging at WARNING (no URLs with
  keys), data files are 0600 and the data dir is gitignored; `logging.raiseExceptions = False` stops a full disk from recursing.
- launchd: `ExitTimeOut 20`, `ThrottleInterval 15`, `Umask 63`, Standard QoS for the app and Background for the watchdog, `PORT` pinned to 8778.
