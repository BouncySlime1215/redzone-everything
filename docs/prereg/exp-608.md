## Model (flag off = grader v43 byte for byte)
`hs_prime_pause` (`--hs-prime-pause`): a Prime target on the hidden stick is ready B + 1 s (pause B s, the 1 s
EXP-601 resume) after its tune, and airs B behind like a YouTube TV target; nothing else changes. YouTube TV keeps
the measured scrub (`scrub_measured`: 15 s keys + one 7.5 s read). The 1.1 s pause overshoot is left out (inside
the 3 s sync noise). Not combinable with `--hs-prime-edge` / `--hs-resync-prime-edge` (Prime is no longer at its
edge, so the app's book and the re-sync pins keep `lag_total` for Prime, as for YouTube TV). Assumes the Prime start
bug (first CENTER only wakes the nav) is fixed (order 3, separate thread): a fresh Prime tune uses the same EXP-601
tune draw as every target.
