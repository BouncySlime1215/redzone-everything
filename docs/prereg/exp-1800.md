# EXP-1800 pre-registration: recap-aligned importance labels for Watch Value

Data Division H (web-scale sports text). Committed BEFORE any recap is pulled, aligned or trained on
(Nov 5 2026). A change after this commit needs a new EXP id ([grading.md](../grading.md) rule 2).
Tag on every dataset and model this row makes: **personal-use, not for commercial release**.

## Hypothesis (Nick, 11:50 PM Nov 4, verbatim intent)

Game recaps aligned to play-by-play by date and teams tell us **which plays humans wrote about**. Used as a
hindsight importance label for Watch Value, they raise **% of oracle** over Watch Value trained on the
win-probability swing alone. If they don't, H stays small.

**North Star line:** % of oracle (`pct_of_oracle`, mean of NFL, NBA, NHL, and per league). Secondary,
report-only: Big plays seen live, Crunch live, `wv_rank_agree`.

## The label (fixed now)

For each play *i* on a TRAIN night, with the league's Watch Value horizon *H* (`HORIZON_S` in
`scripts/train_watch_value.py`, #166):

- **mention(i) = 1** if an aligned recap names a play in (t_i, t_i + H]; else 0.
- A recap "names" a play when the aligner matches a recap sentence to exactly one play of that game by the
  numbers it carries: period, clock or inning, scorer or actor surname, yards / distance, the score after
  the play. A sentence that matches 0 or 2+ plays names nothing (no guessing).
- **Candidate target:** `y' = 0.7 * wv + 0.3 * mention`, where `wv` is #166's swing label, unchanged.
- **Games with no aligned recap:** `mention` is the recap head's probability (below), so coverage gaps do
  not silently turn into "nobody cared". Coverage is reported per league.

**Recap head (soft labels for gaps):** a LightGBM classifier P(mention | the same in-game features
`features_for()` uses). It is trained only on recaps of games **before each league's eval window start**
(NFL before 2025-09-05; NBA before 2026-10-20; NHL before 2026-10-19; [eval-data.md](../eval-data.md)), so
no valid, locked or fresh night ever reaches it. It reads in-game features only, never text.

The 0.7 / 0.3 mix, the horizon and the head's params are fixed here and are not tuned on any split.

## Arms (same features, same LightGBM params, same seeds, same nights)

| Arm | Watch Value target |
|---|---|
| **A0 baseline** | `wv` (#166 as is) |
| **A1 candidate** | `y'` above |
| **A2 placebo** | `y'` with each game's mentions moved to plays drawn at random from the same game (same count per game, seeded). Tests whether any lift is the recap content or just label smoothing |

Each arm drives the decider through the Watch Value path (`scoring.watch_value` on, EXP-015 wiring) in the
pinned backtest with `--oracle` (`scripts/eval_sports.py`, `scripts/eval.py`). Seeds 0, 1, 2.
Everything else is the pinned `data/eval_config.yaml`.

## Nights

- **Fit:** train nights only for every label and model; valid early-stops (redzone/lab/splits.py).
- **Dev grade:** valid nights, per league. Under 8 valid nights in a league = **PENDING** for that league.
- **Locked** (`test`) is read **once**, at the next release read, by the integrator under the frozen grader.
  This row never asks for it.
- **No recap of a valid, locked or fresh night is ever pulled into training.** The aligner refuses dates
  inside those splits (a test in the code PR proves it).

## Success bar (all must hold)

1. **Lift:** A1 − A0 on % of oracle (mean of NFL, NBA, NHL) ≥ **+1.0 pt**, and the night-cluster bootstrap
   95% CI of the delta (2000 resamples of whole nights, seeds pooled within a night) excludes 0.
2. **Not smoothing:** A1 − A2 on % of oracle has its CI lower bound > 0.
3. **No league hurt:** per league, the CI of A1 − A0 includes 0 or favors A1.
4. **Rule #1:** A1 `entries_mid_play` = 0 and high-leverage leaves (`cuts_high`) = 0.
5. **Alignment quality (gate before 1-4 are read):** on a seeded sample of 300 named plays per league, the
   matched play agrees with the recap on every number the sentence carries in ≥ 90% of cases (automatic
   check against the play-by-play, no human labels, no Nick signal).
6. **Coverage (reported, not a pass condition):** share of train games with an aligned recap, per league.
   Under 30% in a league: that league's hard-label result is reported as soft-label only.

Any of 1-4 missed = **FAIL**: recap labels do not ship, and H shrinks to the Wikipedia features for
game importance (EXP-1802) plus the GitHub dataset finds handed to A and D.

## What this costs

Kaggle CPU only (pull, filter, align: est. ~10-20 CPU-h over 2-3 sessions). Training is LightGBM on CPU
(minutes). The decider backtests are the existing harness (~1 h CPU for 3 arms x 3 seeds). No GPU, no
spend, nothing on the Mac.

## Public repo boundary

The repo gets: code, the alignment index (game_id, play_index, recap_id hash, match score, matched
numbers), per-play label counts and the grades. **No recap text, no sentences, no URLs of copyrighted
pages.** Raw filtered text lives only in the private Kaggle dataset `rz-h-webtext` (personal-use tag).
