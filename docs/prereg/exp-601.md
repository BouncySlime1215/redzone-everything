Why: red team item 1 (/mnt/project-files/yttv-research/redteam-buffer.md). `redzone/lab/backtest.py` treats the

stick tunes, pauses B s, then plays (control._hold), and it is not flippable until then.

## Model (fixed now; flag off = today's grader, byte for byte)
- `run(..., hidden_stick=None | "wait" | "live_edge")`, plus `hold_overrun=1.0`. Off by default; every frozen
  result and test stays unchanged with it off.
- One hidden stick, one preload target at a time. Target choice: the real `redzone/standby.py` planner
  (`options` + `Planner.plan`, two_stick.hold_s / min_gain hysteresis) fed from sim state: current, home
  (decider.home_break_visit), back_to (stack[-1]), want (Decision.want), and the live candidates. No replay
  or break classes (the sim has no break forecast for them); a replay switch needs no buffer, as live.
- Preload clock: a new target starts `tune + B * hold_overrun + resume`. Retargeting restarts the clock.
  - tune ~ lognormal through the Nov 4 live press span "tune" (p50 21.61 s, p95 44.74 s: mu = ln 21.61,
    sigma = 0.4424), clipped to [5, 120] s, seeded per run (seed * 7_000_003 + 601).
  - B = the league's timing.behind_live_s for that run. resume = 1.0 s.
- After a switch, the stick we left is still holding the game we left at B: it is ready at once for that game.
  It counts as a preload of that game until the planner retargets it.
- Prime targets: B = 0 always (a tile can't be paused alone, control._buffer_for). Count them.
- A switch whose target is ready: as today (buffered, B behind live).
- A switch whose target is NOT ready:
  - **Arm A, `wait`**: the cut waits until ready (or until preload of it would be ready if it started now).
    The old game stays on screen meanwhile (watching unchanged, arrive_dt += wait, as _apply_defer does). The
    decider is not told: it believes it switched. That approximation is known and accepted.
  - **Arm B, `live_edge`**: the hidden stick re-tunes the target at the live edge (control path "tuned"), so
    the cut lands one tune later: arrive_dt += a fresh tune sample (same lognormal), old game on screen meanwhile,
    then the picture airs unbuffered: switch offset -= B, so Rule #1 is graded on the live edge. That game stays
    unbuffered until the next switch. Live re-checks a safe moment on the visible stick for up to 25 s after the
    tune and drops the switch if none comes (MAX_SAFE_WAIT_S); the replay grades the cut at the tuned time
    without that re-check, which is the pessimistic side. A target tuned but not yet held also airs at B = 0.
