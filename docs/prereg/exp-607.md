# EXP-607: EXP-605 with the re-sync prior pinning Prime at its live edge (Nov 7, 2026)

Owner T9. Integrator freezes before any run. Info-only diagnosis first (asked by the integrator after EXP-605).

## Diagnosis (trace, not a gated run)
`scripts/exp607_trace_prime_belief.py` on EXP-605's NBA seed 0 (fit nights) logs, at every switch decision to a
Prime target, the app's believed delay (`delays.get(target).mu`) vs the true one (the target's lag minus B, since
Prime airs at its edge):
- shipped harness: 33 Prime switch decisions, 0 with belief off by more than 5 s (believed 26.0 = true 26.0).
- resync harness: 36 decisions, **34 off by 90 s** (believed 116.0 vs true 26.0).
Cause: `backtest.run` builds the re-sync pins (`_attach_resync(..., pinned=...)`, backtest.py ~L616-619) as
`lag_total` for every target, and `refresh_model` restores that pin after each tune. EXP-605's `hs_prime_edge`
moved only the delay book's app default, so under `--resync` every tune of a Prime target snaps its belief back
to the buffered 116 s. That is a simulator artifact: live, the re-sync prior is the channel's fresh-tune (edge)
calibration plus `d.behind` (decider/screen.py L252-254), and `held` for an un-held Prime target is 0
(control.py L1475), i.e. its edge, the code facts EXP-605 cites.
With the fix flag on, the same trace gives 33 decisions, 0 off by more than 5 s (diagnostic only; tunes nothing).

`lag_total - B` (its live edge), the same belief EXP-605 gives the book. Nothing else changes.
