# EXP-1723: ledger-weighted Watch Value as the windowed oracle's beyond-window value (WV loop cycle 3)

Tag: personal-use, not for commercial release. Pre-registered Nov 5 2026 before any fit. Locked never read.

## Why
Cycle 2 mistake ledger (NBA fit nights, 90 s buffer, p90 feed lag 70 s; /mnt/project-files/wv-loop/ledger/): vs full hindsight,
wrong_game_value carries 64% of value lost, stay_leave_timing 30%, break_estimate 7%. The windowed oracle with the v1 past-mean
beyond value scores BELOW the app on 6/6 positive nights, so it is not yet a ceiling.

## Arms (only these)
- B0 (control): oracle_window with beyond_value = past mean (v1 placeholder).
- B1: beyond_value = Watch Value A0 (#166, current dev model) per game x horizon, no reweighting.
- B2: B1 with WV retrained using mistake_ledger.sample_weights (1 + value lost of the covering episode) on the ledger rows of nights
  already seen in the forward chain.

## Protocol (forward chain, never-seen nights)
redzone/lab/forward_chain.Chain over NBA then NFL fit nights in time order: each night is scored FIRST with the model trained on
earlier nights only (B2 retrains after each night); that first-pass score is the evidence. Old nights in eval-data-v1 are dev
history; the counting nights are eval-data-v3's new nights + every live night after Nov 5 (locked excluded).

## Metric and bar
Value of the windowed-oracle schedule as % of the full-hindsight oracle (oracle.schedule_value, combined, v1 reward), pooled over
nights without a your-team crunch, night-bootstrap 95% CI, seed 1723.
Pass for B1 or B2: >= +5 points over B0 with CI lower bound > 0 AND >= the app's own % of full on the same nights (it must be a
ceiling for the app to be graded against). The winner becomes the proposed beyond value for oracle_window (integrator freezes).
Secondary (report only): change in the wrong_game_value share of the app's ledger when the app's decider reads the same WV.
