# SYNC plan: creative ways to know exactly where each screen is in real time (Nov 4, 1:35 AM)

Nick: timing/sync is massive. No new features; make it run smoother.

**Core idea:** stop *guessing* each stream's delay and **control and measure** it. If the app knows
"stick 2 is showing reality minus 86.0 s ± 1 s", then every cut and entry can be placed exactly.

## Finding (read-only, tonight)
Each stick's Android media session reports the player state (3 playing, 2 paused, 6 buffering) with
a timestamp. YouTube TV reports position = -1 for live streams. Prime's position on live hasn't been
seen yet; check it during Wednesday's live test.

## Ranked solutions

1. **Set the delay instead of estimating it.**
   - When tuning a game on the hidden stick, seek it to an exact offset behind the live edge (the
     buffer B), using the app's live controls: jump to live, then rewind/pause a known amount.
   - Then the screen delay = the channel's base delay + B. That's known by construction, not
     guessed.
   - Recheck it at every tune. Drift is caught by #3 and #4.

2. **One-time "tap sync" calibration per channel.**
   - On the phone page, Nick taps the moment he sees a score change on TV. The app matches the tap
     to the league feed's exact event time (NHL `utc`, NBA `timeActual`, ESPN `wallclock`), which
     gives that channel's base delay.
   - About 3 taps per network (ESPN, TNT, Prime, FOX, CBS…), stored and reused. The app asks for a
     re-tap only if a channel's measured drift shows up.

3. **Player-state truth from the media session.**
   - Use playing / paused / buffering transitions and their timestamps.
   - **Flip only when the hidden stick reports PLAYING and has been stable for about 1 s.**
   - Any BUFFERING after a flip adds its duration to that stick's delay. Buffering is the main way a
     stream drifts behind.
   - If Prime exposes a position on live, use it as a direct offset reading.

4. **Event anchoring (no screen capture needed).**
   - Every score change and period end has an exact real-world time in the league feeds.
   - When the app *knows* a stream must show an event at T + delay, it checks consistency: did the
     feed and the stick's state agree (for example, the player paused for a break where expected)?
     Mismatches correct the delay estimate.

5. **One clock for everything.**
   - NTP-disciplined Mac clock, all events stamped on a monotonic clock.
   - Use the feeds' server time (`Date` header, event utc) to measure feed lag on every poll.
   - The per-stick delay filter (Kalman) merges #1-#4 into one number with an error bar. The decider
     uses the error bar: when it's wide, cut later and enter later.

6. **Smarter polling for faster dead balls.**
   - Burst-poll (1-2 s) when a stoppage is likely: the clock about to stop, a free-throw sequence,
     a TV-timeout window.
   - Slow-poll otherwise.
   - Use conditional requests (ETag / If-Modified-Since), plus the fastest feed per league (NHL wsc
     pbp, NBA cdn liveData, FastCast).

7. **Settle detection after the flip.** After the TV input switches, watch the target stick's state.
   If it's buffering or not playing within 3 s, fall back (re-tune, or flip back) before Nick
   notices.

8. **A drift alarm with self-heal.** If a stick's measured delay drifts more than 5 s from its plan,
   it gets re-synced at the next dead ball on that game (jump to live, re-apply B). That's invisible,
   because it happens on the hidden stick.

## Metrics (North Star rows)
- Per-stick delay error: p50 and p95, measured against tap-sync and event anchors. **Target p95 ≤ 2 s.**
- Landings in dead time ≥ 95%, 0 mid-play cuts and entries (live, from Wednesday's test on).
- Flip settle: % of flips that are PLAYING within 3 s. **Target ≥ 99%.**

## Order
1. #3 and #7 (the media-session player state). These are cheap and make flips safe now.
2. #1 (the set offset), together with #61's buffer.
3. #2 (tap sync) on the phone page, used during Wednesday's test.
4. #5 (the delay filter with an error bar), feeding the Reflex.
5. #6 (burst polling) and #8 (the drift alarm).
