## 1. Threat model (what "hidden" can and cannot mean here)

- The agents are cooperative optimizers, not attackers. The realistic leaks are accidents: a recursive grep that lands on a results folder, a CI log, a cached archive, a transcript. Literature on agent evaluation shows the optimizing kind of leak is real: models patch or read the scorer, find leaked solutions, or inspect the call stack for reference data [METR 2025], and learning such hacks in training generalizes to broader misbehavior [Anthropic 2025]. A 2026 benchmark audit lists the leak channels as local filesystem, git history, online hosting and task metadata [SWE-Bench Pro Verified; partial read].
- Same-OS-user agents with a shell can read anything the user can. Permission rules, hooks and the sandbox raise the cost and stop accidents; only a separate OS user or a separate machine/CI (a different principal) gives a real lock. So the design has two tiers: Tier 1 (same user, $0, today) and Tier 2 (separate `rzgrader` user plus an environment-gated CI job).
- Goal is not secrecy of the locked data from the world (this repo is public); it is that nobody tunes on it. So the real invariant is "no feedback channel finer than pass/fail per release candidate".

## 3. Tier 1 design: exact config (same OS user)

### 3a. `.claude/settings.json` additions

Path anchors per the permissions docs: `//` is an absolute path, `~/` is home, `/` is relative to the settings source, and a single leading slash is NOT absolute [Permissions docs]. Deny always wins over allow at every settings level, and a PreToolUse hook cannot override a deny rule [Permissions docs]. Use `Read(...)` for Grep/Glob too: `Grep(path)` and `Glob(path)` rules are accepted but never matched [Permissions docs].

```json
{
  "permissions": {
    "deny": [
      "Read(//Users/nick_matta/redzone-vault/**)",
      "Edit(//Users/nick_matta/redzone-vault/**)",
      "Read(./results/locked/**)",
      "Read(./data/locked/**)",
      "Read(./.rz_locked/**)",
      "Edit(./results/summary/**)",
      "Edit(./results/locked/**)",
      "Bash(gh release download eval-locked*:*)",
      "Bash(gh api */actions/artifacts*:*)",
      "Bash(gh run download:*)"
    ]
  },
  "sandbox": {
    "enabled": true,
    "allowUnsandboxedCommands": false,
    "failIfUnavailable": false,
    "filesystem": {
      "denyRead": ["~/redzone-vault", "./results/locked", "./data/locked", "./.rz_locked"],
      "denyWrite": ["~/redzone-vault", "./results/summary", "./.claude", "./.github"]
    },
    "excludedCommands": ["scripts/live_run.sh *", "scripts/grade_locked.sh *"]
  }
}
```

Notes, each from the docs:
- Read/Edit deny rules cover the built-in tools and recognized Bash file commands (`cat`, `head`, `tail`, `sed`, `tee`, redirects) but NOT `grep -r pattern .` from the holding directory or a Python script that opens files itself; the docs point to the sandbox for that [Permissions docs]. The sandbox is off by default and covers Bash and children only, not the Read/Edit/Grep tools, so both layers are needed [Sandboxing docs].
- Sandbox `denyRead` and Read-rule deny are said to merge for subprocesses [Sandboxing docs], but one issue report says Bash reads ignored `Read()` denies on 2.1.126 [claudeissues 55288, snippet-only]. Put the vault in BOTH lists and test (section 3d).
- In project settings `.` resolves to the project root; in user settings it resolves to `~/.claude` [Sandboxing docs]. Keep these entries in the project file.
- `allowUnsandboxedCommands: false` removes the `dangerouslyDisableSandbox` retry; otherwise `bypassPermissions` mode runs the retry with no prompt [Sandboxing docs].
- `excludedCommands` run with full access. They must match text exactly, and the scripts must be uneditable by agents (they are: `scripts/live_run.sh`, `scripts/grade_locked.sh` join PROTECTED) [Sandboxing docs].
- Sandbox network allowlist starts empty; `git push`, `gh`, adb to the TV and pip will need `sandbox.network.allowedDomains` or be excluded. This is the main adoption cost; trial before relying on it [Sandboxing docs].
- Put the whole block in managed settings (`/Library/Application Support/ClaudeCode/managed-settings.json`) if Nick wants workers unable to widen it; managed rules cannot be overridden by any other level [Permissions docs; delivery details live on the linked managed-settings page, not fetched].

Worker versus coordinator: project deny rules apply to every session, coordinator included. That is intended: nobody in a Claude session ever reads raw locked data; the coordinator reads `results/summary/` only (section 6), and runs the live TV tests through the allowed wrappers (section 7).

### 3b. Matcher fix

In `settings.json`, change the PreToolUse matcher to `Bash|Edit|Write|MultiEdit|NotebookEdit|Read|Grep|Glob`. Hooks fire inside subagents too, with `agent_id` and `agent_type` in the input [Hooks docs], so subagents are covered.

### 3c. `guard.py` additions (rule G8 "locked")

Add near the other patterns:

```python
LOCKED = re.compile(
    r"(redzone-vault|results/locked|data/locked|\.rz_locked|eval-locked|locked\.json|grader-private)")
LOCKED_RUN_OK = re.compile(r"^\s*(\./)?scripts/(live_run|grade_locked)\.sh\b")   # the only doors
GH_LEAK = re.compile(r"\bgh\s+(run\s+download|api\b[^\n]*(actions/(runs|artifacts)|releases)|release\s+download\s+eval-locked)")

def check_locked(tool: str, inp: dict) -> None:
    """Fail CLOSED: any doubt about a locked path blocks. Block text names the allowed door."""
    parts = [str(inp.get(k, "")) for k in ("file_path", "path", "glob", "pattern", "command", "notebook_path")]
    blob = " ".join(parts)
    if tool == "Bash" and LOCKED_RUN_OK.match(str(inp.get("command", ""))) \
            and not re.search(r"[;&|`$<>]", str(inp.get("command", ""))[
                LOCKED_RUN_OK.match(str(inp.get("command", ""))).end():]):
        return                                   # a bare wrapper call, no chaining or redirects
    if LOCKED.search(blob) or (tool == "Bash" and GH_LEAK.search(blob)):
        block("G8 locked", "locked data and raw results are not readable by agents (tuning on them is the overfit we forbid).",
              "read results/summary/latest.json; ask the coordinator to run scripts/grade_locked.sh for a release candidate.")
```

Wire it so it runs first and does not fail open:

```python
    # in main(), before the existing try:
    if tool in ("Bash", "Read", "Grep", "Glob", "Edit", "Write", "MultiEdit", "NotebookEdit"):
        try:
            check_locked(tool, inp)
        except SystemExit:
            raise
        except Exception as exc:
            block("G8 locked", f"guard error ({exc}); locked checks fail closed.", "retry, or ask Nick.")
```

Add `results/summary/**`, `scripts/live_run.sh`, `scripts/grade_locked.sh`, `scripts/summarize_results.py`, `grader/**`, `CODEOWNERS` to `PROTECTED`. Also block `Bash` strings that `touch`/redirect `settings.local.json` (it is read from the project `.claude/` folder, so an agent could add allow rules; G6 covers `.claude/**` for Edit/Write but Bash text matching is partial).

Limits (say it plainly): a regex hook sees only the command text. `cd ~ && cat $(echo cmVkem9uZS12YXVsdA== | base64 -d)/x` defeats it. The sandbox `denyRead` and Tier 2 are what stop that.

Optional PostToolUse scrub: the grader prints locked values only after a sentinel `RZLOCK:`; a PostToolUse hook returns `updatedToolOutput` with those lines removed. The hooks docs state PostToolUse can replace tool output [Hooks docs]. It is a backstop for F6, not a primary control.

## 4. Folder layout

```
redzone/                          # repo (worktrees of it are what agents see)
  tests/
    (existing flat test_*.py = unit + integration; do not move 100+ files)
    live/                         # hardware tests; coordinator runs them (G3 flag)
    replay/                       # dev-night replays and scorecards
  grader/                         # NEW, grader-only code: locked loader, summarizer, gates glue
  scripts/live_run.sh grade_locked.sh summarize_results.py   # protected "doors"
  results/
    dev/<date>-<sha>-<suite>.json # full detail, agents may read, gitignored
    summary/latest.json, <runid>.json   # gate booleans + bucketed margins, anyone may read
  CODEOWNERS                      # section 5
~/redzone-vault/                  # OUTSIDE the repo, mode 0700 (Tier 2: owned by rzgrader)
  locked-data/<tag>/              # locked nights (decrypted only at grade time)
  raw/<runid>/                    # raw locked scorecards, raw live-TV logs
  ledger.jsonl                    # one line per locked run (cap: once per release candidate)
```

Why outside the repo: Grep/Glob search a directory by `path`, and Read deny rules are applied to that directory [Permissions docs]. A recursive search from the repo root should not even be able to name the locked folder. Worktrees are created from git, so nothing in the vault ever ends up in an agent's checkout.

Split the data physically: `build_eval_data.py` should emit `eval-data-dev` (train+valid nights plus the pin) and `eval-locked` (test nights only). The dev archive stays a public release. The locked archive is encrypted (`age`, free) and attached to a release; the key is an environment secret in `grader` (section 5). That needs a grader PR touching `scripts/build_eval_data.py`, `scripts/fetch_eval_data.py` and the lock files, so it is Nick's to merge.

   The `*` line is optional; keep it off if Nick does not want to approve every PR (the `integration/next` train merges many). It mirrors `PROTECTED` in `guard.py`, so the local hook and the server agree.
3. Enforcement: a CODEOWNERS file alone blocks nothing. Enable "Require review from Code Owners" in branch protection or a ruleset [Protected branches docs; CODEOWNERS docs]. Admins bypass branch protection unless "Do not allow bypassing" is on [Protected branches docs]; rulesets have an explicit bypass list [Rulesets docs]. Rulesets are available on the Free plan for public repos [GitHub plans, snippet-only]; push rulesets with path restriction are only for private or internal repos, so path locks here must be CODEOWNERS plus the local hook [Rulesets docs].
4. Environment `grader` is the real lock for the locked step. Secrets are only available to jobs that use the environment, and only after its rules pass; required reviewers (up to 6) and deployment-branch limits are available on Free for public repos [Environments docs]. An agent branch that edits the workflow to use the environment still stops at Nick's approval prompt.
5. Job layout in `ci.yml` (grader PR):
```yaml
  locked-gate:
    if: github.base_ref == 'codex/resume-redzone'      # release PR only
    environment: grader
    permissions: { contents: read }
    steps:
      - ... fetch eval-locked asset, decrypt with ${{ secrets.LOCKED_AGE_KEY }} into $RUNNER_TEMP
      - run: python grader/run_locked.py --out "$RUNNER_TEMP/raw.json" --summary summary.json
      - run: cat summary.json >> "$GITHUB_STEP_SUMMARY"   # summary only (section 6)
      - run: rm -rf "$RUNNER_TEMP"/*
```
   Never `set -x`; never `cat raw.json`. Secret masking needs exact-value matches, and structured blobs defeat it, so do not rely on masking to protect locked values; print nothing locked at all [Security hardening docs].
6. Fork PRs get no secrets and a read-only token, and `pull_request_target` or `workflow_run` run with secrets and must never check out untrusted code [Security hardening docs; fork blog 2021, snippet-only]. Keep the locked job off those triggers.

Tier 2 alternative inside CI-free local use: a private repo `redzone-grader` (free) holding the data, called by `repository_dispatch` with a PAT secret. Costs more moving parts and still needs a token Nick makes; the environment route above is simpler. Not recommended unless the encrypted-asset route proves awkward.

## 6. "Summary only" interface

`results/summary/latest.json`, written only by `grader/summarize_results.py`, shape:

```json
{"run": "2026-11-09-rc3", "sha": "abc1234", "split": "locked", "gates": {"entries_mid_play": "pass", "plays_missed_entry": "pass_thin", "dead_air_pct": "fail"}, "ready_to_ship": false, "locked_runs_used": 1}
```
Rules (design choices, not sourced): booleans and three bucket labels (`pass`, `pass_thin`, `fail`) only; no per-night, per-game, per-league-night, per-team or per-play values; no numbers finer than the gate thresholds already published in `docs/architecture.md` section 7; one locked run per release candidate, counted in `ledger.jsonl`, refused when used up; `dev` results stay fully detailed under `results/dev/` so agents still have rich feedback for tuning. The dev/locked split is by whole night with forward-chaining CV as already required by CLAUDE.md; this section only controls who sees the locked side.

## 7. How the coordinator still runs the live TV tests

Live tests are the one place a Claude session needs real hardware, so they use a door, not a read.

1. Nick creates `data/.agent_hw_ok` when he is not watching (rule G3, unchanged).
2. Coordinator runs `scripts/live_run.sh <suite>` (allowed by `Bash(scripts/live_run.sh *)`, excluded from the sandbox so it can reach adb and the vault). The script: runs `pytest -m live tests/live/` with `REDZONE_RESULTS_DIR=~/redzone-vault/raw/<runid>`; splits output into two files, `rehearsal` suites go to `results/dev/` (agents may read, since they debug from them) and `holdout` suites go to the vault; calls `grader/summarize_results.py`; prints only the summary JSON and exits non-zero on failure.
3. Coordinator reads `results/summary/latest.json` and the rehearsal detail. For a failing holdout it reports "holdout fails gate X" and hands workers the rehearsal replay, never raw holdout.
4. Tier 2: Nick adds one sudoers line (`visudo -f /etc/sudoers.d/redzone`) allowing only `nick_matta ALL=(rzgrader) NOPASSWD: /usr/local/libexec/rz-live-run`; the wrapper is root-owned and the vault is `rzgrader:staff 0700`. Then the vault is unreadable to every Claude session regardless of hooks. Creating the user is a system change; Nick does it, not an agent. Verify adb works under that user (its own adb server and key) before relying on it.

## 8. Test tiers, naming and markers

| Tier | Where / marker | Runs | Reads | Notes |
|---|---|---|---|---|
| unit | `tests/test_*.py`, `unit` (default) | every PR, ms | nothing outside `tests/` | small = single process, no I/O, no network [SWE at Google ch. 11] |
| integration | `integration` | every PR | fixtures, dev data | medium = localhost only |
| replay | `tests/replay/`, `replay` | every PR (smoke), nightly (full) | dev nights from `eval-data-dev` | writes `results/dev/` |
| live | `tests/live/`, `live` | coordinator only, G3 flag | the TV | large; keep out of CI [SWE at Google ch. 11] |
| locked | `locked`, code under `grader/` | release PR, environment `grader` | vault | never imported by `redzone/` |

pyproject changes (protected? `pyproject.toml` is not in PROTECTED; add it, since `addopts` can re-enable `locked`):
```toml
markers = [ ... "unit: no I/O", "integration: fixtures or localhost", "replay: dev-night replays",
            "live: needs sticks/TV (coordinator, G3)", "locked: grader-only, never run by agents" ]
addopts = "--strict-markers -m 'not live and not locked'"
```
Unregistered markers only warn without `--strict-markers` [pytest marks docs]. Keep locked tests out of collection entirely for agents with `collect_ignore_glob = ["grader/*", "tests/live/*"]` in a conftest or `--ignore-glob` [pytest collection docs]; CI's grader job overrides it with `-m locked`. Name results `<UTC-date>-<sha7>-<suite>.json` so a run is traceable to code without reading content. Quarantine flaky tests rather than rerunning blindly; about 1% flakiness already erodes trust [SWE at Google ch. 11].

## 9. Failure modes and who closes them

| Failure mode | Closed by |
|---|---|
| `grep -r .` from repo root reaches results | vault outside repo; `results/locked` denied (3a); dev results contain nothing locked |
| `gh run view --log`, `gh run download`, job summary | F1/F2 fix: CI prints summary only; `gh run download` denied; env secrets are masked only on exact match, so print nothing locked |
| Agent uses Nick's gh token to approve the environment or read private data | separate bot identity (section 5.1) |
| Cache (`~/.cache/redzone-eval`, `.pytest_cache`, `--junitxml`, `__pycache__`, shell history) | dev-only cache; locked work only in `$RUNNER_TEMP` or vault; `rm -rf` at end |
| Claude transcripts and persisted tool output (F6) | print nothing locked; PostToolUse scrub; Tier 2 user separation |
| Bash text evasion (base64, `cd ~`, scripts) | sandbox `denyRead` plus Tier 2; hook is a speed bump |
| `dangerouslyDisableSandbox` retry under bypass mode | `allowUnsandboxedCommands: false` |
| Agent edits `.claude/settings.local.json`, hook, CI or CODEOWNERS | G6 plus CODEOWNERS plus ruleset; deny rules win over local allow [Permissions docs] |
| Slow leak by repeated pass/fail queries (adaptive overfitting) | one locked run per release candidate (ledger), coarse buckets |
| Hook crash fails open | G8 locked block fails closed |
| Locked nights inferred from the public lock file (`dev_before`, window) | acceptable: the dates are not the data; keep per-night lists out of git |
